[前回の記事](/articles/006-meishi-bot/)の中で、小さな事件が起きていました。

LINEに名刺の写真を送ると、スプレッドシートに自動保存されるBot。[ダラリ重工業](/company/)（わかりやすさのための、ぼくの架空会社です）が契約している名刺管理アプリを、自作で置き換えられるかの検証で作ったやつです。

そのBotに、うちの猫の写真を送ったら、こう返ってきました。

「申し訳ございません。名刺として認識できませんでした。」

……ん？

なんで分かったんでしょう。

コードを書いたのはAIです。ぼくじゃありません。それどころか正直に言うと、ぼくは最初、あのコードがほぼ読めませんでした。

読めないコードの中の「誰か」が、猫を見抜いた。

「AIだから、なんかいい感じに判定してるんでしょ」

ぼくも最初はそう思っていました。今日はこの事件の犯人を、実物のコードを開けて捜します。

## 先に言い切ります

**犯人は捕まりました。そして、コードが読めなくても捕まえられます。**

犯人を捜して仕組みを一駅ずつ辿る道のりが、そのままこのBotの中身の解説になっています。

しかも犯人の正体が分かると、AIへの直しの頼み方が劇的にうまくなります。

「なんか動かない」ではなく、「ここを直して」と場所を指させるようになる。この差はでかいです！

## 現場検証：開けてみると、ファイル1個でした

現場はGitHub（コードの保管サービス）にある、ぼく専用の非公開リポジトリ（プロジェクトごとの保管箱）です。

開けてみると、本体は app.py というファイルが1個だけ。350行弱です。

しかも、そのうち100行ちょっとは、AIが書いた日本語の説明コメントでした。実際に動くコードは200行くらい。現場、意外と狭いんです。

処理の流れは、写真が届いてから1行増えるまで、駅を順番に通っていく旅になっています。猫は、この旅のどこかの駅で止められたはずです。

> **ことばメモ｜Webhook（ウェブフック）** 「何か起きたら、この住所に知らせて」という仕組みのこと。今回は「LINEに画像が届いたら、ぼくのプログラムに知らせて」という設定を指します。

ここから、名刺の写真と猫の写真、2枚を並べて各駅を回ります。実物のコード数行＋日本語のいいかえを置いていくので、眺めるだけでOKです。

## 捜査開始前に、別件の証拠が出てきました

現場に入ってすぐ、事件とは関係ない証拠がひとつ見つかりました。

前回、「APIキーは家の鍵と同じ。コードに直接書かない」と書きました。その約束の実物です。

```python
load_dotenv()

line_bot_api = LineBotApi(os.getenv('LINE_CHANNEL_ACCESS_TOKEN'))
handler = WebhookHandler(os.getenv('LINE_CHANNEL_SECRET'))
```

いいかえると、「.env という別ファイルから設定を読み込んで（load_dotenv）、LINEのトークンを環境変数（コードの外にある置き場）から取ってくる（os.getenv）」です。

コードのどこを探しても、鍵の実物は書かれていません。あるのは「置き場から取ってこい」という指示だけ。

そして鍵の実物が入った .env ファイルは、.gitignore という除外リストに登録されていて、保管箱にそもそも入らない設定になっています。リポジトリを丸ごと人に見せても、鍵は見えません。

前回の約束、ちゃんと守られていました。答え合わせ完了。捜査に戻ります。

## 駅1：入口——ここで止まるのは「偽物の荷物」だけ

LINEに写真を送ると、LINEのサーバーがぼくのプログラムの住所（Webhook）に知らせてきます。最初の容疑者は、この入口です。

```python
@app.route("/webhook", methods=['POST'])
def webhook():
    signature = request.headers['X-Line-Signature']
    body = request.get_data(as_text=True)
    try:
        handler.handle(body, signature)
    except InvalidSignatureError:
        return 'Invalid signature', 400
```

いいかえると、「/webhook という窓口に荷物が届いたら、まず署名（本物のLINEからの荷物だという証明）を確認。合わなければ門前払い」です。

この住所はインターネット上にあるので、知らない誰かも叩けてしまいます。だから合言葉チェックが一番最初にある。こういう守りの定石が、最初から入っていました。

さて、猫の写真です。

ぼくは本物のLINEから送っています。署名は本物。名刺の写真と、まったく同じ顔で通過します。

入口は、シロ。写真の中身なんて、一切見ていません。

## 駅2：目——文字は探す。でも「猫かどうか」は見ていない

届いた画像をLINEから受け取ったら（ここは数行なので省略します）、Googleの文字読み取りサービス（Vision API）に渡します。

```python
response = client.text_detection(image=image)
texts = response.text_annotations

if texts:
    return texts[0].description
else:
    return None
```

いいかえると、「画像を渡して文字検出（text_detection）。何か読めたら、読めた文字を全部まとめて返す。1文字も読めなかったら『何もなし（None）』と返す」です。

名刺の写真はここで、氏名も電話番号も会社名も順番ばらばらの、1本の文字の塊になります。

じゃあ、目が猫を見抜いた犯人か？

違うんです。この駅の仕事は「文字を探す」、それだけ。「これは名刺だ」「これは猫だ」と判定する機能は、ここにはありません。

目も、シロ。犯人はまだ先にいます。

## 駅3：頭——ここで、指名手配書を発見しました

文字の塊は、ChatGPTのAPI（プログラムから呼び出せる窓口）に渡されます。使っているのはGPT-5-nanoという小さくて安いモデルです。前回「1枚あたり約0.03円」と書けたのは、これのおかげです。

この駅を調べていて、ぼくは固まりました。

AIへの指示文（プロンプト）が、コードの中にそのまま日本語で書いてあるんです。

```text
判定基準:
- 人名、会社名、電話番号、メールアドレス、住所などが
  含まれている場合は名刺として判定
- 風景、食べ物、動物、一般的な文章のみの場合は
  名刺ではないと判定
```

……見つけました。

風景、食べ物、**動物**。

書いてあるじゃないですか。猫の名指しこそしていませんが、これはもう指名手配書です。

このプロンプトで「名刺なら、氏名・会社名・役職・メールアドレス・電話番号の5つを抜き出して、JSON（決まった形のデータ）で返して。名刺じゃないなら is_business_card を false（いいえ）にして」と頼んでいます。

そう、コードの中身は英語の呪文だけじゃないんです。一番大事な判断基準は、普通の日本語で書いてある。

## 駅4：関所——実行役はここにいました

判定結果を受けて、実際にお断りの文を送りつけた実行役が、次の駅にいます。

```python
if not structured_data.get('is_business_card', False):
    line_bot_api.reply_message(
        reply_token,
        TextSendMessage(text="申し訳ございません。名刺として認識できませんでした。\n名刺の画像を明確に撮影して、再度お送りください。")
    )
    return
```

いいかえると、「頭（ChatGPT）が『これは名刺じゃない（false）』と答えたら、お詫びの文を返して、旅をここで打ち切る（return）」です。

ただ、このif文をよく見てください。「猫」のことは何も知りません。falseかどうかを見て、伝言どおりにお断り文を送っただけです。

つまり、こうです。

実行役は、駅4のif文。

でも判断を下した犯人は、駅3のプロンプトに書かれた「動物…は名刺ではないと判定」——**普通の日本語の1行**でした。

うちの猫は、あの2文字に引っかかって、この関所で旅を打ち切られていたわけです。

英語の呪文でも、複雑なアルゴリズムでもありませんでした。事件解決です。

ちなみに、文字が1文字も読めない写真（風景など）は、駅2で「何もなし」となって、同じお断りメッセージが返ります。守りは二段構えでした。

## 駅5：終点——名刺だけがたどり着く場所

猫が来られなかった終点も、見ておきましょう。関所を抜けた名刺データは、スプレッドシートへ向かいます。

```python
values = [[
    current_date,
    data.get('name', ''),
    data.get('company_name', ''),
    data.get('post', ''),
    data.get('mail_address', ''),
    data.get('phone_number', '')
]]
```

いいかえると、「日時・氏名・会社名・役職・メール・電話番号を、この順番で1行分に並べる」です。読み取れなかった項目は空欄（''）にして、旅を止めない作りになっています。

これをシートの末尾に追加（append）して、LINEに「登録完了しました！」と、修正用のシートのリンク付きで返信。旅はここで終わりです。

写真を送ってから1行増えるまで、人間の入力はゼロ。中身は、これで全部です。

## 失敗談：捜査以前に、Botが動かなかった話

実はこの事件の前に、もっと地味な事件がありました。

このリポジトリには、AIとのやり取りの記録も残してあります。そこに、当時のぼくの発言がそのまま残っていました。

「でもさ、LINEに画像をアップしても何も起きないよ」

コード自体は完成していたんです。でも動かない。原因は、コードの外側に転がっていました。

- そもそもプログラムを起動していなかった
- .env に貼ったGoogleの鍵情報を、1行で書くべきところ改行して書いていて、読み込みエラー
- プログラムの窓口番号（ポート5000）が、Macの標準機能とぶつかっていた（5001番に変えて解決）

コードが書けた、イコール動く、ではないんですね。配線が9割でした。

それでも、駅の並びが分かっていたおかげで、「入口まで荷物は届いてるか？」から順番に確認して、ひとつずつ潰せました。

やっていることは、今日の犯人捜しと同じです。旅の全体像を知っておく効き目は、直すときに一番出ます。

## 聞かれそうなことに、先に答えます

**Q1. コードが読めないのに、直せるの？**

直せます。というか、直すのはAIです。

駅の名前が分かっていれば、「返信の文面を作っている関数を、もっとフランクな言い方に直して」と場所を指させます。場所を指させると、AIの直しは速くて正確になります。今日の捜査は、その指差しの練習でもあります。

**Q2. キーが漏れる心配はないの？**

コードには書かない、保管箱にも入れない、というのが今回の作りです（捜査前に出てきた別件の証拠のところです）。

逆に、AIに作ってもらうときに何も言わないと、キーがコードに直書きされることがあります。頼むときに「キーは環境変数から読む形で」の一言だけは、必ず入れてください。

**Q3. 目と頭で、なんでサービスが2つ要るの？**

読み取り（目）はGoogle、仕分け（頭）はChatGPTの分業です。

分けてある利点は、転んだ場所が分かりやすいことです。実際このBotは、画像が取れないとき・名刺と認識できないとき・処理の途中で転んだときで、LINEに返ってくる文が違う作りになっています。

どの文が返ってきたかが、どの駅で止まったかのヒントになる。今日ぼくが「猫はどの駅で止まった？」と辿れたのも、この作りのおかげです。

**Q4. 会社の名刺で使っていい？**

そこは前回と同じ答えです。名刺は個人情報なので、会社でやるなら「入れていい情報」の確認が先。迷ったときの判断のしかたは、[この記事](/articles/014-nyuuryoku-handan/)にまとめてあります。

検証は自分の名刺で。会社の名刺の山は、正規ルートを通してから、です。

## リポジトリを持つのはまだ怖い人へ

GitHubの登録すらまだ、という人も大丈夫です。

AIに作ってもらったコードが手元にあるなら、それを丸ごとAIに貼って、「どこで何が起きてるか、駅ごとに説明して」と頼んでください。今日ぼくがやった捜査を、自分のコードで再現できます。

## 犯人が「日本語」だったことの意味

今日の事件、犯人はコードの奥の英語ではなく、プロンプトの日本語の1行でした。

これ、すごくいい知らせだと思うんです。

Botの一番大事な判断基準が日本語で書いてあるなら、直すのも日本語でできます。「読めないから触れない」は、思い込みでした。

そして、外注のSaaSと自作の一番の違いもここです。外注サービスの中身は開けられません。自分のリポジトリなら、中身を開けて、指を差せる。直す権利ごと、手元にあるんです。

今日の一歩です。AIに作ってもらったものが何かあるなら、そのコードを貼って、こう聞いてみてください。

「このコード、どこで何が起きてるか、順番に日本語で説明して」

自分のBotの中の「犯人たち」が見えたら、次の直しはもう、あなたが指差せます！
