取れた理由（次に更新する人へ）:

- JIS本文は **JISC（日本産業標準調査会）で無料閲覧できる**。`https://www.jisc.go.jp/app/jis/general/GnrJISSearch.html` → 規格番号で検索 → 規格番号をクリック → 詳細画面の「**音声PDF**」は**ログイン不要**でテキスト入りPDFが取れる（通常PDFはログイン要）。サイトに「閲覧は可能だが印刷・購入はできない」と明記されているので、**転載はせず出典として引くだけにする**
- 同サイトには「**JIS規格の使用単語からJISを検索**」機能があり、**どの語がJISで何件使われているか**を数えられる（POSTのため直リンク不可。上記検索ページのフォームに語を入れる）
- 法令は e-Gov の API（`https://elaws.e-gov.go.jp/api/1/lawdata/<法令ID>`）で全文XMLが一発で取れる。人間用URLは `https://laws.e-gov.go.jp/law/<法令ID>`

**2026-08-15 追記 ― 官公庁の配布ZIP／旧Excelの数え方（ハマりどころ）**

厚労省の業種別ZIP（職業能力評価基準）は中身が**旧形式の `.xls`（BIFF）**。ここで数え方を2回間違えた。記録しておく。

1. **`unzip` はファイル名が化けて失敗することがある**が、**Pythonの `zipfile` は日本語ファイル名をそのまま読める**。ファイル名の日本語を再エンコードし直すと逆に壊れる（`cp437→cp932` 変換を噛ませて全滅させた）
2. **`.xls` を生バイトで grep してはいけない。** BIFFは文字列を共有テーブルに1回だけ持つので、**セルに何十回出てくる語も1回としか数えられない**（実際に「ジグ 45」と出たが、正しくは76）
3. 正しくは **`xlrd` で全シート・全セルを読んで数える**（`pip install xlrd`。システムPythonがPEP668で弾くので `python3 -m venv` を切ること）。**`.xls` は xlrd 2.x でも読める**（読めなくなったのは `.xlsx` のほう）

### ⬛ 「ジグ」の正確な件数は出せない（前回の🔴宿題1の結論。2026-08-15 確定）

JISCの単語検索は **AND / OR / NOT に対応している**（検索式の説明ページ https://www.jisc.go.jp/site/shiki.html で確認。ANDは空白区切りで省略可）。
そこで「ジグ NOT ジグザグ」等で500件の上限を割ろうとしたが、**基底語が500件を超えていると集合演算の結果が破綻する**ことが実測で分かった。

| 検索式 | 画面の表示 |
|---|---|
| ジグ | **500件超**（件数非表示・エラー画面に飛ぶ） |
| ジグ NOT ジグザグ | **500件超** |
| ジグ AND 工作 | **63件** |
| ジグ NOT 工作 | **500件超** ← 63件を除いてなお500件超。この時点で内訳が取れない |
| ジグ AND 機械 | **500件超** |
| ジグ NOT 機械 | **240件** ← ANDが500件超なのにNOTが240件。**合計が総数と噛み合わない** |

**対照実験（基底語が小さければ演算は正しい）**: 治具＝**8件** ／ 治具 AND 機械＝**6件** ／ 治具 NOT 機械＝**2件**。**6＋2＝8で完全に一致**。
→ **破綻の原因は演算子ではなく、「ジグ」が500件の上限を超えていること。** 分割による総数の算出は不可能。

**したがって、これは🔴宿題ではなく⬛（これ以上取りに行っても取れない）に落とす。**
記事で書けるのは「**JISの本文で500件以上の規格が「ジグ」を使っている（正確な数はJISCの検索システムの上限で数えられない）**」まで。

### 🔧 jig と fixture の使い分け（公的に定義あり）

**JIS B 3000:2020 が 2034 と 2035 を隣り合わせで別項目に立て、対応英語を jig / fixture と振り分けている。**
