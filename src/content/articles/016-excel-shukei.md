毎月、あの日が来ます。

各装置の日報Excelをかき集めて、稼働率を計算して、エラー件数を数えて、不良率を出して、月次の表に転記する。

気づいたら夕方。今月も1日仕事です。

「しかもこれ、間違えられないんだよな……」

そうなんです。単純作業のくせに、集中力だけは要求してくる。いちばん疲れるタイプの仕事ですね。

こんにちは、だらリーヌです！

ぼくは製造業のJTC企業で、製造部門のAI活用推進を担当しています。職場ではClaude Teamを7名で導入して、日々の業務をAIでカイゼンしています。

今日は、毎月の手作業集計の話です。

言い切ります。**その集計、来月からは「手順を書く仕事」に変わります。**

毎月手を動かすのではありません。手順を1回だけAIに書かせる。来月からは、実行して、結果を確認するだけです。

## そもそも、なぜ毎月同じ作業をしているのか

毎月の集計って、よく考えると変なんです。

日報の形式は毎月同じ。やる手順も毎月同じ。同じ手順の繰り返しは、機械がいちばん得意なことです。

なのに人間がやっている。理由はひとつで、**手順をプログラムにできる人が職場にいなかったから**です。

いまは違います。プログラムはAIが書きます。あなたがやるのは「何をどう集計したいか」を日本語で説明することだけです。

> **ことばメモ｜プロンプト** AIへの指示文のこと。この記事では、コピペしてそのまま使えるプロンプトの例を3つ載せています。

## 実例: 装置の稼働率・エラー件数・不良率の月次集計

説明するより、実物を見るのが早いです。

今回の舞台は、[ダラリ重工業](/company/)です（わかりやすさのための、ぼくの架空会社です）。実物の集計画面はお見せできないので、製造業の月例行事「設備稼働集計」を、ダラリ重工業の社内イントラにページごと作って再現しました。

👉 実物がこれです: [設備稼働集計（月次）— DARARIポータル](/company/intranet/kadou-shukei/)

![設備稼働集計ページの画面。装置ごとの稼働率・エラー件数・不良率の月次確定値表と、AIスクリプトによる毎朝7時の速報値表が並ぶ。集計方法の履歴には「各課がExcelで手集計・約1日半」から「AIスクリプトによる自動集計・約3分」への切り替えが記録されている](/images/articles/016-kadou-shukei.jpg)

集計方法の履歴を見てください。手集計で約1日半かかっていたものが、いまは約3分。この記事は、その「切り替え」のやり方の話です。

加工機3台、組立ライン2本、検査装置1台。毎月、各課が日報のExcelから各装置の稼働率・エラー件数・不良率を手で集計して、このページに転記していました。所要時間、約1日半。

それが2026年8月から、AIに書かせたプログラムでの自動集計に変わりました。所要時間、約3分。しかも月に1回だった数字が、毎朝更新の速報になっています。

「うちの月報とそっくりなんだけど」

そう見えたなら、この記事はあなたのための記事です。ここから、この状態までの道のりを3段で説明します。

## やってみた: 道具の階段は3段です

難しい方に行くほど強力です。でも、非エンジニアは1段目からで大丈夫です。

### 1段目: AIに貼って聞く

表をそのままAIに貼って、「この形式で集計して」と頼む方法です。登録も設定も要りません。

```
この日報の表を、装置ごとの月次集計にしてください。
・列は「装置名」「稼働率」「エラー件数」「不良率」の4列
・稼働率は、稼働時間の合計÷計画時間の合計を％で
・不良率は、不良数の合計÷生産数の合計を％で
・稼働率が低い装置から順に並べてください

（ここに日報の表を貼り付け）
```

これだけで、集計とレイアウトまで返ってきます。

ChatGPT（有償プラン）やClaudeなら、この程度は一発です。両方使っているぼくの感覚だと、2026年8月現在、少しClaudeのほうが優秀かな？と思います。意図を汲んでくれるんですよね。

ただし弱点があって、**来月もまた貼る必要があります**。それと、貼っていいデータかの確認が先です。これはあとで書きます。

### 2段目: AIに関数・数式を書かせる

「装置ごとに、条件に合う行だけ拾って集計したい」

こういう集計、SUMIFSやCOUNTIFS（条件に合う行だけを合計したり数えたりするExcel関数）が組めれば一瞬なんですが、組める人が少ない。だからAIに組ませます。

```
Excelの数式を作ってください。
・シート「日報」のB列に装置名、E列に稼働時間、
　F列に計画時間が入っています
・装置「NC旋盤2号機」の稼働率を出したいです
　（稼働時間の合計÷計画時間の合計を％で）
貼り付ける数式をそのまま出してください。
数式の意味も、1行ずつ日本語で説明してください。
```

1段目との違いは、**式がファイルに残ること**です。

来月は、新しい日報を貼れば式が勝手に計算します。もうAIに聞き直す必要すらありません。

### 3段目: AIに集計プログラムを書かせる

最終形です。毎月ファイル名だけ変えて実行すれば終わる状態にします。ダラリ重工業の集計ページが8月からそうなったのは、この段です。

```
毎月の設備稼働集計を自動化するプログラムを、Pythonで書いてください。
・フォルダに「設備日報_202608.xlsx」のような名前のファイルが毎月増えます
・指定した月のファイルを読み込み、装置ごとに
　稼働率（稼働時間の合計÷計画時間の合計）、
　エラー件数の合計、
　不良率（不良数の合計÷生産数の合計）を計算してください
・結果は「稼働集計_202608.xlsx」という名前で、同じフォルダに保存してください
・実行するのはプログラムに詳しくない人です。
　実行の手順も、日本語で1から説明してください
```

Python（無料で使えるプログラミング言語）と聞くと身構えますよね。でもコードを書くのはAIです。

あなたの仕事は2つだけ。「何をどう集計したいか」を日本語で説明すること。そして、動かして結果を確認することです。

「本当にできるの？」と思いますよね。この記事を書きながら、実際にやってみました。

ダミーの日報CSV（138行）を用意して、上とほぼ同じ頼み方でAIにスクリプトを書かせて、実行した画面がこれです。

![AIが書いた集計スクリプトを実行した結果の画面。装置ごとの稼働率・エラー件数・不良率が表になっている。日報138行からこの表まで、実行1回・約1秒](/images/articles/016-shukei-demo.jpg)

頼んでから、この表が出るまで数分。実行そのものは約1秒でした。

ぼくは実際に、ポンコツPC（Celeronでメモリ4GB）でも動く自動集計を作りました。集計プログラムはゲームと違って軽いので、職場の古いPCでも動きます。

エラーが出たら、そのエラー文をコピーしてAIに貼るだけです。「直しました」と修正版が返ってきます。

## 貼る前に: そのデータ、外に出していいですか

ここ、この記事でいちばん大事です。

稼働率や不良率は、工場の実力がそのまま見える数字です。顧客名や金額が入っていなくても、**そのまま外部のAIに貼るのは、アウトの会社が多いです。**

うちの会社のAI利用は「申請すれば使える」制度です。あなたの会社のルールがどうなっているかを、先に確認してください。何を確認すればいいかは[入れていい情報のルール](/articles/002-ai-rules-starter/)にまとめています。ダラリ重工業の[AI入力情報基準](/company/ai-nyuryoku-kijun/)みたいに判断表がある会社なら、自分のデータと使うAIの交点を見るだけです。

そして、ルール的に貼れないデータでも、逃げ方があります。

- **固有名詞を伏せる**: 装置名を「装置A」「装置B」に置き換えてから貼る
- **数値をダミーにする**: 稼働時間や不良数を適当な数字に差し替えた表で、手順だけ作らせる。**数式もプログラムも、中身がダミーでも同じものができます。** できた手順を、本物のデータに社内で当てるだけです

集計の手順に、機密は含まれません。だから「手順を書く仕事」は、データを外に出さずにできるんです。

## 失敗談: 検算せずに出しかけました

かっこ悪い話をします。

AIに作らせた集計結果を、そのまま報告に使いかけたことがあります。

出す直前に、念のため元の表の合計と突き合わせたら、数字が合わない。冷や汗が出ました。

原因はAIではなく、ぼくの説明でした。集計から除きたい行があったのに、それを伝えていなかった。AIは言われたとおりに、全部の行を足していました。

稼働集計でいえば、休日や計画停止の行を除き忘れて、稼働率が実際より低く出るような話です。現場に濡れ衣を着せかねません。

この経験からの教訓はひとつです。**生成AIは間違えることがある。これはバグではなく仕様です。**

だから、AIが出した集計は、必ず1回は自分で検算する。合計が元データと合っているかを見る。この確認までが工程です。

逆に言うと、3段目まで行けば検算はラクになります。プログラムは一度正しく動けば、来月も同じ動きをするからです。毎月ゼロから検算するのは最初だけです。

## 想定問答: これ、聞かれます

**Q1.「装置の稼働データをAIに貼っていいの？」**

会社によります、で終わらせません。確認する場所は決まっています。AI利用のルールと、情報の機密区分です。ルールが見当たらないなら、[この記事](/articles/002-ai-rules-starter/)の3点を情シスに聞いてください。それまではダミーデータで手順だけ作るのが安全です。

**Q2.「会社のPCにPythonなんて入れられないんだけど」**

なら2段目までで戦えます。Excelの数式は、どの会社のPCにも最初から入っています。3段目に行きたくなったら、情シスに「集計の自動化に使いたい」と申請しましょう。堂々と便利になるのが正規ルートです。

**Q3.「マクロ（VBA）と何が違うの？」**

やりたいことは同じです。あなたの会社がVBAなら動かしやすいなら、AIへの頼み方を「Pythonで」から「ExcelのVBAで」に変えるだけです。大事なのは言語ではなく、**自分でコードを書かないこと**です。

**Q4.「AIが集計を間違えたら責任問題では？」**

間違える前提で工程を組みます。検算してから出す。これは人間の部下に集計を頼むときと同じですね。確認せずに出したら、それは頼んだ側の仕事の抜けです。

**Q5.「毎月、日報の形式が微妙に変わるんだけど」**

あるあるですね。変わったら、またAIに「列が1本増えたので直して」と頼むだけです。修理も日本語でできるのが、この方法のいいところです。

## AIに貼れない・PCに何も入れられない人へ

全面禁止の会社でも、できることがあります。

**データを1行も貼らずに、構造だけ説明する**方法です。

「A列に日付、B列に装置名、E列に稼働時間、F列に計画時間が入った表があります。装置ごとに稼働率（稼働時間の合計÷計画時間の合計）を出す数式をください」

これなら、外に出ているのは列の並びだけです。機密は1文字も出ていません。

それと、集計の元データを社内システムから落とす操作が分からないときは、画面をAIに見せて聞くワザがあります。[別の記事](/articles/008-shanai-system/)で深掘りしています。

## 今日の一歩

毎月いちばん憂鬱な集計を、ひとつ思い浮かべてください。

装置の稼働率でも、売上でも、経費でもかまいません。

そして、データは貼らずに、列の構造だけをAIに説明して、数式を1本もらってみてください。

「え、こんな日本語で数式が返ってくるの」

その驚きが、手作業集計の引退届です。来月のあなたは、実行して確認するだけの人になっています！
