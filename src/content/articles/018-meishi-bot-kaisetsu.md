「AIがコードを書いてくれた。動いた。……で、中身は？」

[前回の記事](/articles/006-meishi-bot/)で、LINEに名刺の写真を送るとスプレッドシートに自動保存されるBotを作りました。[ダラリ重工業](/company/)（わかりやすさのための、ぼくの架空会社です）が契約している名刺管理アプリを、自作で置き換えられるかの検証でした。

あのとき、正直に書かなかったことがあります。

AIが出してきたコード、ぼくも最初はほぼ読めませんでした。

「読めないものを動かして大丈夫なの？」「ブラックボックスのままなの？」

今日はこの声に、実物のコードを開けて答えます。

## 先に言い切ります

**コードは読めなくていいです。**

でも「どこで何が起きてるか」は、知っておく価値があります。

それが分かると、AIへの直しの頼み方が、劇的にうまくなるからです。

「なんか動かない」ではなく、「返信メッセージを作っているところを直して」と言えるようになる。この差はでかいです！

## 開けてみると、ファイル1個でした

今回のBotの中身は、GitHub（コードの保管サービス）にある、ぼく専用の非公開リポジトリ（プロジェクトごとの保管箱）に入っています。

開けてみると、本体は app.py というファイルが1個だけ。350行弱です。

しかも、そのうち100行ちょっとは、AIが書いた日本語の説明コメントでした。実際に動くコードは200行くらい。意外と小さいんです。

処理の流れは、写真が届いてから1行増えるまで、駅を順番に通っていく旅になっています。

> **ことばメモ｜Webhook（ウェブフック）** 「何か起きたら、この住所に知らせて」という仕組みのこと。今回は「LINEに画像が届いたら、ぼくのプログラムに知らせて」という設定を指します。

ここから、駅ごとに「実物のコード数行＋日本語のいいかえ」を置いていきます。眺めるだけでOKです。

## 出発前に、鍵の置き場所の答え合わせ

前回、「APIキーは家の鍵と同じ。コードに直接書かない」と書きました。実物ではこうなっています。

```python
load_dotenv()

line_bot_api = LineBotApi(os.getenv('LINE_CHANNEL_ACCESS_TOKEN'))
handler = WebhookHandler(os.getenv('LINE_CHANNEL_SECRET'))
```

いいかえると、「.env という別ファイルから設定を読み込んで（load_dotenv）、LINEのトークンを環境変数（コードの外にある置き場）から取ってくる（os.getenv）」です。

コードのどこを探しても、キーの実物は書かれていません。あるのは「置き場から取ってこい」という指示だけ。

そして鍵の実物が入った .env ファイルは、.gitignore という除外リストに登録されていて、保管箱にそもそも入らない設定になっています。リポジトリを丸ごと人に見せても、鍵は見えません。

前回の約束、ちゃんと守られていました。

## 駅1：入口——荷物の受け取りと合言葉

LINEに写真を送ると、LINEのサーバーがぼくのプログラムの住所（Webhook）に知らせてきます。入口はここです。

```python
@app.route("/webhook", methods=['POST'])
def webhook():
    signature = request.headers['X-Line-Signature']
    body = request.get_data(as_text=True)
    try:
        handler.handle(body, signature)
    except InvalidSignatureError:
        return 'Invalid signature', 400
```

いいかえると、「/webhook という窓口に荷物が届いたら、まず署名（本物のLINEからの荷物だという証明）を確認。合わなければ門前払い」です。

この住所はインターネット上にあるので、知らない誰かも叩けてしまいます。だから合言葉チェックが一番最初にある。こういう守りの定石が、最初から入っていました。

## 駅2：目——写真から文字へ

届いた画像をLINEから受け取ったら（ここは数行なので省略します）、Googleの文字読み取りサービス（Vision API）に渡します。

```python
response = client.text_detection(image=image)
texts = response.text_annotations

if texts:
    return texts[0].description
else:
    return None
```

いいかえると、「画像を渡して文字検出（text_detection）。何か読めたら、読めた文字を全部まとめて返す。1文字も読めなかったら『何もなし（None）』と返す」です。

この駅を出た時点では、まだただの文字の塊です。氏名も電話番号も会社名も、順番ばらばらの1本のテキストになっています。

## 駅3：頭——文字の塊を仕分ける

その塊を、ChatGPTのAPI（プログラムから呼び出せる窓口）に渡します。使っているのはGPT-5-nanoという小さくて安いモデルです。前回「1件あたりコンビニのレシート1枚より安い」と書けたのは、これのおかげです。

面白いのはここです。AIへの指示文（プロンプト）が、コードの中にそのまま日本語で書いてあります。

```text
判定基準:
- 人名、会社名、電話番号、メールアドレス、住所などが
  含まれている場合は名刺として判定
- 風景、食べ物、動物、一般的な文章のみの場合は
  名刺ではないと判定
```

そう、コードの中身は英語の呪文だけじゃないんです。一番大事な判断基準は、普通の日本語で書いてある。

このプロンプトで「名刺なら、氏名・会社名・役職・メールアドレス・電話番号の5つを抜き出して、JSON（決まった形のデータ）で返して。名刺じゃないなら is_business_card を false（いいえ）にして」と頼んでいます。

## 駅4：関所——猫はここで止まる

前回、「名刺じゃない写真（うちの猫です）を送ると、ちゃんと断ってくれる」と書きました。その仕掛けの実物がこれです。

```python
if not structured_data.get('is_business_card', False):
    line_bot_api.reply_message(
        reply_token,
        TextSendMessage(text="申し訳ございません。名刺として認識できませんでした。\n名刺の画像を明確に撮影して、再度お送りください。")
    )
    return
```

いいかえると、「頭（ChatGPT）が『これは名刺じゃない（false）』と答えたら、お詫びの文を返して、旅をここで打ち切る（return）」です。

さっきの判定基準に「動物」って書いてありましたよね。うちの猫は、あの1行に引っかかって、この関所で止まっていたわけです。

ちなみに、文字が1文字も読めない写真（風景など）は、ひとつ前の駅で「何もなし」となって、同じお断りメッセージが返ります。守りは二段構えでした。

## 駅5：終点——スプレッドシートに1行増える

関所を抜けた名刺データは、最後にスプレッドシートへ向かいます。

```python
values = [[
    current_date,
    data.get('name', ''),
    data.get('company_name', ''),
    data.get('post', ''),
    data.get('mail_address', ''),
    data.get('phone_number', '')
]]
```

いいかえると、「日時・氏名・会社名・役職・メール・電話番号を、この順番で1行分に並べる」です。読み取れなかった項目は空欄（''）にして、旅を止めない作りになっています。

これをシートの末尾に追加（append）して、LINEに「登録完了しました！」と、修正用のシートのリンク付きで返信。旅はここで終わりです。

写真を送ってから1行増えるまで、人間の入力はゼロ。中身は、これで全部です。

## 失敗談：コードは完成したのに、何も起きない

このリポジトリには、AIとのやり取りの記録も残してあります。そこに、当時のぼくの発言がそのまま残っていました。

「でもさ、LINEに画像をアップしても何も起きないよ」

コード自体は完成していたんです。でも動かない。原因は、コードの外側に転がっていました。

- そもそもプログラムを起動していなかった
- .env に貼ったGoogleの鍵情報を、1行で書くべきところ改行して書いていて、読み込みエラー
- プログラムの窓口番号（ポート5000）が、Macの標準機能とぶつかっていた（5001番に変えて解決）

コードが書けた、イコール動く、ではないんですね。配線が9割でした。

それでも、駅の並びが分かっていたおかげで、「入口まで荷物は届いてるか？」から順番に確認して、ひとつずつ潰せました。旅の全体像を知っておく効き目は、直すときに一番出ます。

## 聞かれそうなことに、先に答えます

**Q1. コードが読めないのに、直せるの？**

直せます。というか、直すのはAIです。

駅の名前が分かっていれば、「返信の文面を作っている関数を、もっとフランクな言い方に直して」と場所を指させます。場所を指させると、AIの直しは速くて正確になります。今日の解説は、その指差しの練習でもあります。

**Q2. キーが漏れる心配はないの？**

コードには書かない、保管箱にも入れない、というのが今回の作りです（出発前の答え合わせのところです）。

逆に、AIに作ってもらうときに何も言わないと、キーがコードに直書きされることがあります。頼むときに「キーは環境変数から読む形で」の一言だけは、必ず入れてください。

**Q3. 目と頭で、なんでサービスが2つ要るの？**

読み取り（目）はGoogle、仕分け（頭）はChatGPTの分業です。

分けてある利点は、転んだ場所が分かりやすいことです。実際このBotは、画像が取れないとき・名刺と認識できないとき・処理の途中で転んだときで、LINEに返ってくる文が違う作りになっています。どの文が返ってきたかが、どの駅で止まったかのヒントになります。

**Q4. 会社の名刺で使っていい？**

そこは前回と同じ答えです。名刺は個人情報なので、会社でやるなら「入れていい情報」の確認が先。迷ったときの判断のしかたは、[この記事](/articles/014-nyuuryoku-handan/)にまとめてあります。

検証は自分の名刺で。会社の名刺の山は、正規ルートを通してから、です。

## リポジトリを持つのはまだ怖い人へ

GitHubの登録すらまだ、という人も大丈夫です。

AIに作ってもらったコードが手元にあるなら、それを丸ごとAIに貼って、「どこで何が起きてるか、駅ごとに説明して」と頼んでください。今日ぼくがやったのと同じ解説を、自分のコードで受けられます。

## 自分の保管箱を持つ、ということ

外注のSaaSと自作の一番の違いは、月額の話だけじゃありません。

**中身を開けて、指を差せることです。**

外注サービスの中身は開けられません。「読み取る項目を1個足してほしい」と要望は出せても、いつ叶うかは向こう次第です。

自分のリポジトリなら、「app.py のこの関数を、こう直して」とAIに頼んで、すぐ試せます。直す権利ごと、手元にあるんです。

今日の一歩です。AIに作ってもらったものが何かあるなら、そのコードを貼って、こう聞いてみてください。

「このコード、どこで何が起きてるか、順番に日本語で説明して」

自分のBotの旅路が見えたら、次の直しはもう、あなたが指差せます！
