# 資料庫 収録規約

このフォルダは **AIカイゼンHPの弾薬庫**。記事・教材・稟議に貼れる「出典つきの事実」だけを溜める。
作った理由: 過去のリサーチが `10_drafts/ネタ帳.md` に「調査結果の全文はこのセッションの会話ログ参照」と
書かれたまま失われかけていたから（2026-08-14 第2弾リサーチ）。**会話ログを一次保管場所にしない。**

## この資料庫の役割分担

| | やること | やらないこと |
|---|---|---|
| **Opus（弾薬庫番）** | 事実・数値・出典URLを集めて置く | 解釈・記事本文・文体判断・検品 |
| **Fable（執筆・裁定）** | ここを引いて記事を書く／方針を決める | 素材集めの手作業 |

Opusは**解釈を入れない**。「これは使える」「これは強い」等の評価は書かない。
唯一許す注記は**紐付けタグ**（`10_drafts/ネタ帳.md` のどの行・どの記事番号に対応するか）だけ。

## 🔴 絶対規約（捏造ガード）

Opus系モデルがこの手の作業でやらかす最大の事故は
**「もっともらしい数値を、もっともらしいURLと一緒に書く」**こと。
後から検証できず、記事に載って崩れる。以下は例外なく守る。

1. **実際にfetchできた本文から取れた数値だけ書く。** 記憶・推測・「相場的にこのくらい」で書かない
2. **取れなかったら空欄にせず `🔴要手動確認` と明記する。** 穴は埋めるな、見せろ
3. **出典URLは「実際に開いたページのURL」を書く。** トップページや検索結果のURLで代用しない
4. **取得日を全件に入れる**（価格・制度は変わる）。形式 `2026-08-15`
5. **一次 / 二次を明示する。** 一次=発行元自身の公開物（料金ページ・官公庁PDF・自社プレスリリース）／
   二次=まとめ記事・解説ブログ。**二次だけの事実は「二次のみ」と明記**し、一次で裏が取れたら差し替える
6. **引用は短く、リンク中心**（著作権）。原文の丸写し・長文転載・要約による実質再現をしない
7. 判断に迷ったら**書かずに `🔴要手動確認` に落とす**。網羅した風より、穴が見えている方が資産になる

## 🚦 穴の3分類（2026-08-15 改訂）

初版は穴を全部 `🔴要手動確認` で表していたが、**性質の違うものが混ざって324件に膨れ**、
「穴だらけの資料庫」に見える設計ミスになった。以下の3つに分ける。

| 記号 | 意味 | 対応 | 見分け方 |
|---|---|---|---|
| ⬛ **非公開** | 発行元がそもそも公開していない | **対応不要。これ自体が結論** | 「記載なし」「要問い合わせ」「資料請求のみ」「非公開」。埋めるには営業に問い合わせるしかないもの |
| 🔴 **宿題** | 取りに行けるはずなのに取れていない | **次の調査で潰す** | bot遮断・404・PDF未開封・URL未特定・JS未描画。**公開されている**が、こちらの都合で取れなかったもの |
| 🟠 **本人待ち** | darari本人しか埋められない | 一覧にして本人に渡す | ログイン必須（AI Studio等）／社内の記憶・見積の内訳／掲載可否の判断 |

**⬛は穴ではない。** 「調べた結果、公開されていなかった」という**確定した事実**として扱う。
記事で「各社は価格を公開していない」と書く根拠になるのは⬛の方であり、これは資産である。

**負の発見**（「〜が見つからなかった」「競合が薄い」等）は⬛でも🔴でもなく、
**本文に「負の発見・出典URLなし」と明記**して、断定に使わないこと。

数え方: 各ファイル冒頭は `⬛非公開: N件 ／ 🔴宿題: N件 ／ 🟠本人待ち: N件` の3本立てで書く。

## エントリの型

各ファイル内は、1事実1行のテーブルを基本にする。

```markdown
| 項目 | 値 | 一次/二次 | 出典URL（実際に開いたページ） | 取得日 |
|---|---|---|---|---|
| ○○ 月額（最小プラン） | 9,800円/月 | 一次 | https://example.com/pricing | 2026-08-15 |
| ○○ 初期費用 | 🔴要手動確認（料金ページに記載なし・要問い合わせ） | 一次 | https://example.com/pricing | 2026-08-15 |
```

ファイル冒頭には必ずこの3行を置く:

```markdown
最終更新: 2026-08-15
収録者: Opus / 規約: ../00_収録規約.md
🔴要手動確認の残数: N件
```

## フォルダ構成

| No | フォルダ | 中身 | 主な使い道 |
|---|---|---|---|
| 00 | （このファイル・INDEX） | 規約と索引 | Fableはまず `00_INDEX.md` だけ読めば全体が分かる |
| 01 | `01_SaaS価格台帳/` | 社内チャットボットSaaS等の**公開価格**の実物 | Brain教材2,980円の核「SaaS実費 月7万＋初期20万」の裏取り／記事005（費用対効果）／稟議 |
| 02 | `02_競合_無料の壁/` | AIスクール・明鏡等の**無料/有料の境界線** | サイト目的＝市場破壊の的（無料拡充をどこに撃つか） |
| 03 | `03_官公庁一次資料/` | ガイドライン・白書・法令解説の**公開PDF索引** | ガバナンス軸の全記事／稟議に貼れる出典／ネタ帳への出典紐付け |
| 04 | `04_過去調査アーカイブ/` | 会話ログにしか無かった過去リサーチの**サルベージ** | 資産の消失防止 |

## 更新の作法

- 新しくファイルを足したら **`00_INDEX.md` に1行足す**（1行1件。索引に無いものは無いものとして扱う）
- 価格・制度は古びる。**取得日が6ヶ月以上前のものは、引用前に取り直す**
- `🔴要手動確認` を潰したら、その行の取得日を更新する
