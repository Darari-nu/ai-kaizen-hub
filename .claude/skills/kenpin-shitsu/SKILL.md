## 更新手順（記事を直したら毎回これ）


そのあとArtifactツールで再発行する。パラメータは固定:

- `file_path`: `/tmp/kenpin.html`
- `url`: 上記の検品室URL（**必須**。同じアドレスを維持するため）
- `favicon`: 🔎（変えない。本人がタブのアイコンで見分けるため）
- `capabilities`: 省略する（保存済みのmcp宣言がそのまま引き継がれる）
- `label`: 何を反映したかの短い名前（例「003再構成+004修正」）

## 検品メモの書き方（build-kenpin.mjs の NOTES）

```js
'003-chatgpt-kinshi': { status: 'fix', note: '8/7の加筆を取り込み、約2割圧縮しました。…' },
```

- `status: 'ok'` … 本人が検品OKと言ったもの。✅検品ずみと表示され、冒頭のカウントに入る
- `status: 'fix'` … 指示を反映したので再検品してほしいもの。🔄と表示
- `status: 'new'` … まだ見てもらっていない新記事。🆕と表示（NOTESに書かなければ自動でこれ）
- `note` … **何をどう直したかを具体的に書く**。「修正しました」ではなく「Aを→Bに変え、Cは判断待ち」まで書く。
  darariはここだけ読んで差分を把握するので、ここが雑だと全文を読み直させることになる

## 回収手順（本人が「検品回収して」と言ったら）

1. Googleドライブを `title contains '検品_'` で検索（`mcp__claude_ai_Google_Drive__search_files`）
2. 新しいものから `download_file_content` で取得（base64が返るのでデコードして読む）
3. **リポの現行版と見比べる**。ドライブ版が古い版ベースのこともあるので、機械的に上書きしない。
   本人が加筆した箇所だけを拾って、現行版に統合する
4. 統合したらビルド・機械検査・push・検品室の再発行まで通す
5. 回収済みのドライブファイルは消さない（本人の記録として残す）

## 挿絵について

Artifactは外部ホストへ通信できないので、**画像は必ず埋め込みにする**。ページ全体で16MB以内。

## 検品書のルール（2026-08-17 darari指示で正本化。どのセッションのAIもこれに従う）

まとめ書き（複数本を一括執筆→一括検品）の運用がこのリポの標準になった。検品に出すまでの決まり:

1. **入庫前ゲート（順番厳守）**: 執筆（`bunshou-kaizen-loop`の注入テンプレ使用）→ 機械検査NGゼロ → **AI臭セルフチェック**（`10_drafts/20_添削の学び/AI臭チェック_だらリーヌ版.md`）→ **Codexセカンドオピニオン検品**（RULES F6）→ **事前添削**（`ikehaya-tensaku`フレーム＋RULESで診て、軽微修正は反映・判断が要るものは検品メモへ）→ NOTES登録 → 検品室再発行
2. **検品メモの2階建て**:
   - 個別メモ = `build-kenpin.mjs` の NOTES（記事ごと。**確認事項は3つまで**に絞る。B4申告=推測で補った箇所・体験の裏付けが薄い箇所を必ず転記）
   - 横断メモ = `10_drafts/60_回覧資料/検品メモ_*.md`（バッチ単位の総括。反映済みの報告と🔴要判断リストを分け、**「番号+OK/こう直せ」の一言で返せる形**にする）
3. **本人原文の記事化ルール**: darariがチャット/Obsidianに投げた雑文は `10_drafts/素材_darari原文_*.md` に原文のまま保存（本人の言葉が正）。記事化したら「原文から変えた箇所」をNOTESに列挙する
4. **記事以外（新設ページ等）の検品**: `10_drafts/60_回覧資料/検品ページ紹介/*.md` に紹介文を置くと検品室にP-番号で載る（build-kenpin.mjsが自動読込）
5. **図解・OGPは検品後に一括生成**: 執筆時は `<!-- 図解: 指示 -->` コメントで埋め、発注書 `10_drafts/70_図解/発注書_*.md` にプロンプトを起こしておく。生成は検品OK後（文言が変わると図解も変わるため）
6. **未公開のUI・ページはpushしない**: 「push→検品室」の原手順は記事（draft:trueで公開されない）向け。**新設ページはpushすると即公開される**ため、darariの公開OKが出るまでコミット・pushを止め、検品室のページ紹介で見せる
7. **公開URLの表示**: 検品室の各エントリに公開予定URL（`https://darari-nu.com/articles/<slug>/` 等）を表示する（build-kenpin.mjsが自動生成）。darariが「公開後にどこに載るか」をその場で確認できるようにするため

## トークンの話（本人からの質問への回答）

同じURLに再発行しても、**古い版の内容がコンテキストに読み込まれるわけではない**ので、URLを使い回すこと自体にトークンの不利はない。
コストがかかるのは「既存Artifactを読む」とき（WebFetchで全文が入る）と、記事本文を何度も会話に貼るとき。
つまり**URLは固定したまま、チャットに全文を貼らない**のが一番安い。この運用がそのまま最適。
