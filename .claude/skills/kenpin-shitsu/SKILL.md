# 検品室スキル（このリポの文章検品スタイル・2026-08-07 darari指示で標準化）

darariは会社PC・スマホ・自宅PCを行き来する。だから**検品はチャットではなく、1枚のWebページ（Artifact）で行う**。
本人が言った採用理由: 「会社のPCでもできるし、スマホでもできるし、めちゃくちゃいい」。

## 鉄則

1. **同じURLを使い続ける**。新しいURLを生やさない
   - 検品室URL: `https://claude.ai/code/artifact/81fd4910-daef-412b-bc58-13b13cf7f122`
   - 別セッションから更新するときは、Artifactツールの `url` パラメータにこのURLを渡す（渡さないと新URLが生える）
2. **保存先はGoogleドライブ**。GitHubコネクタは使わない（2026-08-07: 本人環境で繋がらなくなったため変更）
3. **検品が済んだものは一目で分かるようにする**（`status` フィールド。下記）
4. **挿絵も一緒に見せる**（サムネを埋め込む。本人「挿絵まで見れると尚いい」）

## 更新手順（記事を直したら毎回これ）

```bash
cd /Volumes/DevSSD/Vibe_Website/260805_Darari-nu_HP
node 10_drafts/tools/build-kenpin.mjs      # → /tmp/kenpin.html を生成
```

そのあとArtifactツールで再発行する。パラメータは固定:

- `file_path`: `/tmp/kenpin.html`
- `url`: 上記の検品室URL（**必須**。同じアドレスを維持するため）
- `favicon`: 🔎（変えない。本人がタブのアイコンで見分けるため）
- `capabilities`: 省略する（保存済みのmcp宣言がそのまま引き継がれる）
- `label`: 何を反映したかの短い名前（例「003再構成+004修正」）

## 検品メモの書き方（build-kenpin.mjs の NOTES）

```js
'003-chatgpt-kinshi': { status: 'fix', note: '8/7の加筆を取り込み、約2割圧縮しました。…' },
```

- `status: 'ok'` … 本人が検品OKと言ったもの。✅検品ずみと表示され、冒頭のカウントに入る
- `status: 'fix'` … 指示を反映したので再検品してほしいもの。🔄と表示
- `status: 'new'` … まだ見てもらっていない新記事。🆕と表示（NOTESに書かなければ自動でこれ）
- `note` … **何をどう直したかを具体的に書く**。「修正しました」ではなく「Aを→Bに変え、Cは判断待ち」まで書く。
  darariはここだけ読んで差分を把握するので、ここが雑だと全文を読み直させることになる

## 回収手順（本人が「検品回収して」と言ったら）

1. Googleドライブを `title contains '検品_'` で検索（`mcp__claude_ai_Google_Drive__search_files`）
2. 新しいものから `download_file_content` で取得（base64が返るのでデコードして読む）
3. **リポの現行版と見比べる**。ドライブ版が古い版ベースのこともあるので、機械的に上書きしない。
   本人が加筆した箇所だけを拾って、現行版に統合する
4. 統合したらビルド・機械検査・push・検品室の再発行まで通す
5. 回収済みのドライブファイルは消さない（本人の記録として残す）

## 挿絵について

`build-kenpin.mjs` が `sips` で幅720pxのjpegサムネを作り（`/tmp/kenpin-thumbs`）、dataURIで埋め込む。
Artifactは外部ホストへ通信できないので、**画像は必ず埋め込みにする**。ページ全体で16MB以内。

## 検品の前にやること（順番を守る）

1. 記事の機械検査を通す（`_template.md` のgrep。禁止表現0件）
2. `npm run build` が緑
3. push（検品室は「pushされた版」を見せる建て付け）
4. そのあと検品室を再発行して、本人に「更新しました」と伝える

## トークンの話（本人からの質問への回答）

同じURLに再発行しても、**古い版の内容がコンテキストに読み込まれるわけではない**ので、URLを使い回すこと自体にトークンの不利はない。
コストがかかるのは「既存Artifactを読む」とき（WebFetchで全文が入る）と、記事本文を何度も会話に貼るとき。
つまり**URLは固定したまま、チャットに全文を貼らない**のが一番安い。この運用がそのまま最適。
