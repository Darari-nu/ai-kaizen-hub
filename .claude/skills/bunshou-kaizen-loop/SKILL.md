# 文章カイゼン・ループ（このリポの自己学習の仕組み・2026-08-08 darari指示）

同じ指摘を二度受けないための仕組み。darariが検品で直した箇所は、**その場の修正で終わらせず、
次回の執筆ルールに変換して蓄積する**。

## このリポにおける「文章の正本」の在処（迷ったらここ）

| 何 | どこ | 役割 |
|---|---|---|
| 記事の型と機械検査 | `src/content/articles/_template.md` | 8ブロック構成・grep検査。**機械で守れるルール** |
| 検品から抽出した執筆ルール | `drafts/添削の学び/RULES.md` | **人の判断が要るルール**。このスキルが育てる |
| 文体の人格・語り口の正本 | `~/Claudecode/260307_2nd-Brain/00_システム/00_UserProfile/03_執筆スタイル(Style_Guidelines).md` | ペルソナの根っこ（全レーン共通） |
| ネタ | `drafts/ネタ帳.md` | ★=一次体験の裏付けあり。ここからしか書かない |
| 旧・添削原則（凍結） | `~/Claudecode/260307_2nd-Brain/43_JTC_AI推進室/_guides/` | 2026-08-05以前の資産。参照はするが、新しい学びはこのリポに書く |

**記事を書く前・サブエージェントに書かせる前は、必ず `RULES.md` を読む（読ませる）こと。**

## ループの1周（毎回この順で回す）

### 1. 回収

Googleドライブを `title contains '検品_'` で検索し、前回の回収以降に増えたファイルを
`download_file_content` で取得する（base64が返るのでデコードして読む）。
同じ記事が複数あるときは**タイムスタンプが最新のものだけ**を採用する。

### 2. 差分をとる

**機械的に上書きしない。** ドライブ版が古い版ベースのことがある。
リポの現行版と読み比べ、**darariが手を入れた箇所だけ**を拾って統合する。
拾ったら、その差分を次のどれかに分類する。

| 分類 | 例 | 行き先 |
|---|---|---|
| **文体** | 「証明できない」→「目に見える証明が難しい」 | RULES.md の D/E/F |
| **事実** | 数字の訂正、年契約の矛盾 | 記事に反映＋RULES.md の B |
| **安全** | 会社が特定される、事故につながる | RULES.md の A/C（最優先で鉄則化） |
| **構成** | 長い、主張がぼやける、ボツ | RULES.md の E |
| **一回限り** | その記事固有の事情 | RULES.mdに入れない（増やしすぎない） |

### 3. ルールに昇格させる

`drafts/添削の学び/RULES.md` を更新する。書き方の掟:

- **必ず「根拠」列に、どの記事のどの修正から学んだかを書く**（日付つき）。根拠のないルールは作らない
- 同じ趣旨のルールが既にあるなら、**新規追加ではなく観測回数を+1する**
- 観測2回以上で「鉄則」扱い。以後は迷わずそれに従う
- 一般論・べき論を勝手に足さない。**実際に指摘されたことだけ**

### 4. 機械で守れるものは機械に落とす

RULES.mdに入れた項目のうち、grepで検出できるものは `_template.md` の検査コマンドに追加する。
（例: 「※」「——」「私は」「僕は」。人名や部署名の実名は辞書を作れば検出できる）
人の判断が要るものだけをRULES.mdに残すのが理想の状態。

### 5. ログを残す

`drafts/添削の学び/log/YYYYMMDD_記事NN.md` に、その回の
「本人が直した箇所 / 分類 / ルールに昇格させたか」を短く残す。
あとで「なぜこのルールがあるのか」を辿れるようにするため。

### 6. 反映して閉じる

記事修正 → 機械検査 → `npm run build` → push → 検品室を再発行（`kenpin-shitsu` スキル）。
本人には「何を直したか」と「何をルールにしたか」を1つずつ報告する。

## 執筆時の使い方（ループの出口）

新記事を書くとき、また**サブエージェントに書かせるとき**は、渡すプロンプトに必ず含める:

1. `_template.md` の8ブロック構成と機械検査
2. **`drafts/添削の学び/RULES.md` を読ませる**（特に A会社特定 / B創作禁止 / C安全 は必須）
3. 文体の見本として `004-claude-team.md`（本人が一番気に入っている文体。ただし完全に寄せない）
4. 使ってよい実体験を**明示的に列挙**し、「これ以外の体験・数字を創作するな」と縛る
5. 補った推測は最後に**申告させる**（検品メモに転記して本人に判断してもらう）

## やってはいけないこと

- 本人の加筆を「文体が整っていないから」と勝手に直すこと。**本人の言葉が正**。明らかな誤字だけ直す
- ルールを一般論で膨らませること。増えすぎたRULESは誰も読まなくなる
- 回収済みのドライブファイルを消すこと（本人の記録として残す）
