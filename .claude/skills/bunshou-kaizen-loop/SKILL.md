# 文章カイゼン・ループ（このリポの自己学習の仕組み・2026-08-08 darari指示）

目的はひとつ: **同じ指摘を二度受けない**。darariが検品で直した箇所を、その場の修正で
終わらせず、次回の執筆ルールに変換して蓄積する。

darariの依頼原文（8/8）:
> 「僕が追記したものは検品回収した後に差分を取り込んで、分析、次回から各ルールに
> 改善点として入れ込めるように自己ループSKILL作ってください。」

隣の工程との分担: **kenpin-shitsu** は検品の物流（Artifact提示・ドライブ回収・記事への反映）。
**このスキル** は同じ回収物からの学習（ルールへの変換）。回収は1回、やることは2つ。

## 入力は2系統ある（片方だけ見ると取りこぼす）

1. **チャット・スマホでの口頭指摘** — 実は学びの大半はこっち（1〜3巡目の鉄則はほぼ全部これ）。
   本人から指摘が来たら、記事を直すだけで流さず、その日のログに書き留める
2. **検品室からの本人直接加筆** — Googleドライブの「検品_」ファイル（4巡目の形）。
   回収の物理的手順は `kenpin-shitsu` スキルの回収手順に従う

## ループの1周（毎回この順で回す）

### 1. 回収

- 口頭指摘: 会話からその場で拾う
- 加筆: ドライブを `title contains '検品_'` で検索し `download_file_content` で取得
  （base64をデコード。同じ記事が複数あればタイムスタンプ最新のみ採用）

### 2. 差分をとる

**機械的に上書きしない。** ドライブ版が古い版ベースのことがある。リポの現行版と読み比べ、
**darariが手を入れた箇所だけ**を拾って統合する。

**本人の言葉が正。** 加筆の言い回しを文体理由で直さない。直してよいのは明らかな誤字だけ。

### 3. 分類する

拾った差分を1件ずつ、次のどれかに分類する。

| 分類 | 例 | 行き先 |
|---|---|---|
| **会社特定** | 部署名・実数・サービス名がバレる | RULES.md A（最優先） |
| **事実** | 数字の訂正・既出記事との矛盾・盛り | 記事に反映＋RULES.md B |
| **安全** | 事故につながる置き換え・禁止行為の無警告 | RULES.md C（最優先） |
| **読者・相手の扱い** | 言い過ぎ・切り捨て・提案が大仕事 | RULES.md D |
| **構成・わかりやすさ** | 長い・脱線・専門用語・手順が粗い | RULES.md E |
| **文体** | トーンの寄せ方 | RULES.md F |
| **企画の却下** | 「だめ」「ボツ」と言われた提案・表現 | RULES.md G（蒸し返し禁止） |
| **一回限り** | その記事固有の事情 | 記事にだけ反映。RULESに入れない |

### 4. ルールに昇格させる

`10_drafts/20_添削の学び/RULES.md` を更新する。掟:

- **根拠必須**: darariの言葉の引用＋日付＋記事番号。根拠のないルール・一般論は作らない
- 同じ趣旨のルールが既にあれば、**新規追加ではなく観測回数を+1**し、根拠を追記する
- **観測2回で鉄則**。加えて、本人が「禁止」「だめ」「ボツ」と言い切ったものは**1回でも即鉄則**
  （2回目を待つと同じ事故をもう一度起こす）
- 却下された企画・表現は **G に追記**（もう提案しない）
- ルールIDは**振り直さない**（欠番可）。ログから辿れなくなるため

### 5. 機械で守れるものは機械に落とす

正規表現で検出できるものは `10_drafts/20_添削の学び/ng-rules.json` にルールとして追加し、
RULES.mdからは外す（例: 「※」「——挟み込み」「私は」。実在の部署名・サービス名も辞書化すれば検出できる）。
**RULES.mdには人の判断が要るものだけを残す**のが理想の状態。

ng-rules.json は Hooks で自動実行される（2026-08-15導入。`.claude/settings.json` +
`scripts/bunshou-check.mjs`）。対象ファイル（`src/content/articles/*.md`・`10_drafts/10_substack/**`）を
Write/Edit した直後に検査が走り、NGはエージェントに自動でフィードバックされる。
セッション終了時にも再検査され、NGが残っていると完了できない。

ルール追加の掟:
- **good（直し方・グッドパターン）は必須**。禁止だけ並べるとエージェントは避け方が分からず不自然な回避文を書く
- **severity** は、文脈によらず常にNGなら `error`、文字通りの意味なら可（比喩の「柱」等）なら `warn`
- **検品済みの既存記事で使われている表現をerrorにしない**。追加前に必ず
  `ls src/content/articles/*.md | grep -v _template | xargs node scripts/bunshou-check.mjs` で誤検出ゼロを確認する
- idは振り直さない（欠番可）。削除でなく `"enabled": false` で無効化できる

### 6. ログを残す

`10_drafts/20_添削の学び/log/YYYYMMDD_件名.md` に短く残す:

- 指摘・加筆の内容（本人の言葉のまま）／分類／どのルールに昇格・加算したか
- **再発の有無**: 既に鉄則だったルールが今回また指摘されたか。
  再発していたら、ルールではなく**注入の仕方**が悪い（手順「執筆時の注入」を強める）

### 7. 反映して閉じる

記事修正 → `_template.md` の機械検査 → **AI臭セルフチェック**（`10_drafts/20_添削の学び/AI臭チェック_だらリーヌ版.md` の検査表） →
**Codexセカンドオピニオン検品**（RULES F6・2026-08-18 darari指示。`codex exec` にAI臭・読みにくさの指摘を出させ、妥当なものを反映） →
`npm run build` → push → 検品室を再発行（`kenpin-shitsu` スキル）→ 本人に「何を直したか」「何をルールにしたか」を報告する。

## 執筆時の注入（ループの出口・ここまでがこのスキルの範囲）

機械検査はHooksが自動で行うので、書けばその場で指摘が返る。人の判断が要るルール
（RULES.md）の注入は引き続き手動で行う。

記事執筆はFableサブエージェント並列が標準（013〜017実績）。サブエージェントはこのスキルを
読まないので、**渡すプロンプトに次のブロックを毎回貼る**（パスは絶対パスのまま渡す）:

```
執筆前に必ずReadすること:
1. /Volumes/DevSSD/Vibe_Website/260805_Darari-nu_HP/src/content/articles/_template.md
   （8ブロック構成と機械検査。公開前にgrep検査が0件になること）
2. /Volumes/DevSSD/Vibe_Website/260805_Darari-nu_HP/10_drafts/20_添削の学び/RULES.md
   （darari本人の検品から抽出したルール。「鉄則」は絶対に守る。特にA会社特定/B創作禁止/C安全）
3. 文体トーン見本: /Volumes/DevSSD/Vibe_Website/260805_Darari-nu_HP/src/content/articles/001-jtc-ai-jijou.md
   （第1話がトーンの基準。※004を見本にするのは2026-08-18 darari指示で廃止）
   文体の規則: 1文1行を基本・句点のあと改行・体言止め多用しない・「って」→「という」
   （イケハヤ添削くん文体ルール。詳細は ikehaya-tensaku スキル）
4. /Volumes/DevSSD/Vibe_Website/260805_Darari-nu_HP/10_drafts/20_添削の学び/AI臭チェック_だらリーヌ版.md
   （AI臭の6分類検査表。提出前に自分の原稿を上から照合する。「家風としてOK」の項も読むこと）

縛り:
- 使ってよい実体験・数字は次に列挙するものだけ: （ここに列挙する）
  これ以外の体験・数字・固有名詞を創作しない
- 体験の裏付けが薄い箇所は、無理に埋めず薄いまま書き、「ここは実体験があれば
  足してください」と申告する（darariは引きがあると自分で足してくれる）
- 提出前に、自分の原稿をRULES.mdの鉄則に照合すること
- 資料にない推測で補った箇所を、最後に列挙して申告すること
```

回収した申告は検品メモ（`kenpin-shitsu` のNOTES）に転記する。
本人への確認事項は**3つまで**に絞る（013〜017で機能した形式）。

## ループの健全性（ときどき見る）

- ログの「再発」欄が続けて埋まるなら、注入テンプレに当該ルールを個別転記して強める
- RULESが増えすぎたら統合する（1グループ10個が目安）。読む気が失せたルール集は存在しないのと同じ

## やってはいけないこと

- 本人の加筆を「文体が整っていないから」と直すこと。**本人の言葉が正**。明らかな誤字だけ直す
- 根拠のないルール・一般論・べき論でRULESを膨らませること
- 回収済みのドライブファイルを消すこと（本人の記録として残す）
- ルールIDの振り直し
